# Spec: 商品(Item)管理

- ステータス: Implemented
- 関連plan: `plan.md`

## 概要

在庫管理・カタログ系アプリケーションの土台となる、商品(Item)の CRUD 機能。
spec駆動開発ワークフローの実装例(worked example)を兼ねる。

## ユーザーストーリー

- API利用者として、新しい商品を登録したい。なぜなら在庫に商品を追加する必要が
  あるから。
- API利用者として、商品を1件、または一覧で取得したい。なぜなら在庫状況を確認
  したいから。
- API利用者として、商品の一部の項目だけを更新したい。なぜなら価格改定など、
  変更が一部の項目に限られる場合があるから。
- API利用者として、不要になった商品を削除したい。

## 機能要件

- **FR-001**: システムは `name` (1〜200文字, 必須) と `price` (0以上, 必須) を
  受け取り、商品を新規作成できること。`description` は任意。
- **FR-002**: システムは商品を1件、IDを指定して取得できること。存在しない場合は
  404 を返すこと。
- **FR-003**: システムは商品を一覧取得できること。`limit` (1〜100, 既定20) と
  `offset` (0以上) でページングできること。
- **FR-004**: システムは商品の一部の項目 (`name` / `description` / `price` の
  いずれか、または組み合わせ) を部分更新できること。存在しない場合は 404 を
  返すこと。
- **FR-005**: `name` / `price` はドメイン上 non-nullable であるため、部分更新
  リクエストで明示的に `null` を送った場合は 422 で拒否すること (`description`
  は nullable なので `null` を送って値をクリアできる)。
- **FR-006**: システムは商品をIDを指定して削除できること。存在しない場合は 404
  を返すこと。

## 非機能要件

- 公開APIの形は OpenAPI スキーマと一致し、schemathesis による契約テストで
  継続的に検証されること。

## スコープ外

- 認証・認可。
- 在庫数量や倉庫といった、商品マスタ以外の概念。
