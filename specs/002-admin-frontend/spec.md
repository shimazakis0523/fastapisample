# Spec: 管理フロントエンド + デプロイ

- ステータス: Implemented
- 関連plan: `plan.md`

## 概要

商品(Item)をブラウザから操作できる管理フロントエンド(Next.js)を追加し、Vercelに
デプロイする。バックエンド(FastAPI)はRailwayに、DBはRailway管理のPostgresに
デプロイする。

## ユーザーストーリー

- 管理者として、ブラウザで商品の一覧・作成・編集・削除をしたい。なぜなら
  `curl`/Swagger UIを使わずに日常的な運用ができるようにしたいから。
- 開発者として、バックエンドを本番相当のPostgresを使う環境にデプロイしたい。
  なぜならSQLiteでは複数インスタンス・永続性の面で本番運用に向かないから。

## 機能要件

- **FR-101**: 管理フロントエンドは商品一覧を表示できること (id/name/description/price)。
- **FR-102**: 管理フロントエンドから新規商品を作成できること。
- **FR-103**: 管理フロントエンドから既存商品を編集できること。
- **FR-104**: 管理フロントエンドから商品を削除できること (確認なしの即時実行でよい)。
- **FR-105**: バックエンドは管理フロントエンドのオリジンからのクロスオリジン
  リクエストを許可すること (CORS)。許可オリジンは環境変数で設定可能なこと。
- **FR-106**: バックエンドは `postgres://` / `postgresql://` 形式のDB接続文字列を
  受け取った場合、非同期ドライバ(`asyncpg`)向けに自動的に正規化すること
  (マネージドPostgresの多くがこの形式でURLを払い出すため)。
- **FR-107**: コンテナ起動時にマイグレーション (`alembic upgrade head`) を実行
  してからアプリケーションサーバーを起動すること。
- **FR-108**: コンテナはPaaSが注入する `PORT` 環境変数でリッスンできること。

## 非機能要件

- 認証: 対象外 (スコープ外に明記)。管理フロントエンドは現時点で無認証。

## スコープ外

- 管理フロントエンド・APIへの認証/認可。
- 商品一覧のページング・検索・ソートといった高度なUI機能。
- CI/CDパイプラインの自動デプロイ設定 (手動でのRailway/Vercel接続を前提とする)。

## 未解決事項

- 無し (認証は将来のspecで扱う)。
